# Loctek AI OS 项目复现入口

## 使用方式

把本仓库交给 AI 后，让它先读本文件，再按“页面入口 → 结果基线 → 代码快照 → 验收记录”的顺序执行。页面需要使用者自己登录，账号和权限由现有 OS 账号提供。本仓库不保存任何凭证。

仓库内所有文件都使用相对链接；源码原始位置通过 GitLab 链接说明，不依赖某台电脑的目录。

最新结果的事实口径：

- 业务反馈 104 行：85 条已确认，19 条未确认并有备注。
- 定点处理 164 封：140 组标签变化，24 组复核后保留。

- 另有 2 条旧 validator 差异在结果中标注。

重点边界：

- I07/O06 需求确认必须有明确选型、确认参数或决定性修改；尺寸询问、规格讨论和模糊意向不算确认。
- O09 样品安排必须是明确安排或执行；PI、开 PI、未来计划出货和内部让工厂安排不自动算新样品；追问已有样品和新样品请求分开。
- I14 订单确认必须是实际下单、确认订单或修改已有订单；“希望下单”和暂定柜量仍是讨论。
- PI 不误标成报价；运费询问不误标成物流；价格讨论保留 I08；普通问候不标 C01；选中样品清单按 I07/I08 优先级去重。
- Validator 不要求原文必须出现 `confirm`。某个次级标签证据不足时，只拒绝该标签，保留其他有独立证据的标签。

### 邮件复现步骤

1. 先打开正式页面，查看老版本可视化结果，确认当前服务器仍是 8.7/8.x 基线。
2. 再读取本仓库的老结果和最新结果，先对比“说明”工作表，再抽查“逐封对比”。
3. 使用本仓库的最新代码快照阅读规则和校验逻辑；不需要访问某台电脑的目录。
4. 抽样覆盖 19 条未确认反馈、上述四类边界以及 164 封定点处理范围。
5. 对每封抽样记录正文、规则证据、`topics`、`actions`、`business_labels`、`risk_signals`、`confidence` 和 `needs_review`。
6. 新问题要标注行号、实际标签、预期标签、是否属于 3 条已知数据缺口，再交给邮件 owner。

## 三、统一输出格式

每个项目输出一份运行记录：

| 字段 | 内容 |
|---|---|
| 项目 | 评论 / 邮件 |
| 页面入口 | 正式页面 URL |
| 代码入口 | GitLab 链接或本仓库代码目录 |
| 结果基线 | 老结果、新结果或评论测试报告 |
| 运行时间 | 开始和结束时间 |
| 结果 | 成功、部分成功、阻断或失败 |
| 证据 | 页面截图、请求阶段、历史 ID、响应摘要、导出文件 |
| 已知问题 | 区分老版本差异、下游问题和新发现问题 |
| 责任人 | 评论 owner 或邮件 owner |

## 四、权限和数据边界

- 使用现有 OS 账号登录，不把账号、密码、API key、数据库连接串或 SSH 私钥写入仓库。
- 本仓库是私有项目，邮件结果和评论报告只给有权限的项目成员使用。
- 复现阶段只读、抽样和记录证据，不执行批量重打、删除、迁移或发布。
